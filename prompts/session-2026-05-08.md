## Notes / decisions
- **Next 16 API change.** `revalidateTag(tag)` now requires a 2nd `profile` arg. Switched to `updateTag(tag)` from `next/cache`, which is the modern read-your-own-writes API for server actions and matches our intent exactly.
- **Onboarding page split.** The original `page.tsx` was a single `'use client'` file. Per the prompt's "Cleanest pattern" guidance, page.tsx is now a Server Component that fetches `getEnabledArchetypes()` and passes the array to a new `OnboardingClient.tsx` (the wizard).
- **Grep gate uses plain `node` + `.mjs`.** Avoided extra deps (`globby`, `tsx`) per the prompt's "no extra deps if possible" hint. Allowlist includes archetype-specific server actions (`sos.ts`, `admin-sos.ts`, `archetype.ts`, `onboarding.ts`), the migration banner, the equipment-taxonomy ROLES list (where `'logistics'` is a different namespace — a ROLE option, not an archetype), the dev seed script, and the two test files that need to assert on disabled-archetype behavior.
- **Marketing copy review.** No marketing surface promises functionality the launch archetypes don't cover. Pricing copy mentions "dealers and enterprises" but that framing is broader than the trader archetype — operators and service providers can also subscribe to Pro/Business and act as dealers commercially. No copy commented out.
