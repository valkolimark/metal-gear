## Unresolved gaps

1. **`registry_seeding` is uninstrumented at the script layer.** `scripts/seed-equipment-registry.ts` calls Anthropic directly but doesn't import `recordAiUsage` (script context, separate runtime). Acceptable for now — the script is run manually a handful of times. If we re-run after meaningful manufacturer data updates, instrument before running.
2. **`unstable_cache`-wrapped `/api/search/ai`** logs only on cache miss. Cached responses don't fire telemetry — a feature, not a bug, since cached responses don't hit the API. Worth noting for anyone reading the dashboard who sees lower call counts than expected for AI search.
3. **Email + display name for top-users table.** I deliberately omitted email from the surface (avoid PII bleed into ops dashboards). Display name comes from `profiles.display_name` / `profiles.full_name`. If an admin needs the email, they click through to `/admin/users/{id}`.
4. **No `view_financials` permission gate inspection done for `analyst` role tightening.** Inherited from `/admin/snap-list-metrics` — analyst role already has `view_financials`. No change.

## Operational notes

- The migration is idempotent (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`). Safe to re-run.
- Telemetry is fire-and-forget, so a flaky `ai_usage_events` insert path can't break a Photo-to-Listing analysis. If we see telemetry-related Sentry noise, the platform is still operating normally.
- Cost numbers in the dashboard are estimates. Trust the Anthropic + Google Cloud consoles for billing reconciliation. The dashboard is for trend-spotting and anomaly detection.
