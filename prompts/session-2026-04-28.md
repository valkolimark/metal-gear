# Cycle 63 — User-Facing AI Feedback Loop ("Was this right?")

Added inline `SuggestionFeedbackChip` next to AI-populated fields on the Photo-to-Listing review screen and the SOS sent step. Three states (accepted / rejected / unsure), append-only writes via two server actions: `recordSuggestionFeedback()` (non-registry → new `ai_suggestion_feedback` table) and `recordRegistryFeedbackFromChip()` (manufacturer/model → Cycle 61's `registry_match_feedback`). Both actions fail-soft — return `{ ok: false, error }` rather than throwing — and check ownership against `listing_drafts.owner_id` / `sos_requests.requester_id` / `listings.seller_id`. Admin breakdown rendered on `/admin/snap-list-metrics` aggregates accept/reject/overridden/unsure counts per field across the last 30 days, UNION-ing both feedback tables and deduping latest-per-user-per-field client-side. Hot-flags fields with >40% reject share + ≥5 events for prompt iteration. Migration applied via Supabase Management API; RLS enabled with `feedback insert own` policy. Deviation surfaced in the changelog: the manual-form photo helper was NOT wired this cycle — no `listings` row exists pre-save, so there's no `source_row_id` to attach pre-publish feedback to. Same constraint resolved on the SOS surface by deferring chips to the post-create `SOSSentStep`. Component, action, RLS, and admin breakdown are all in place to slot the manual-form helper in as soon as a transient draft layer exists. typecheck/lint/build pass; vitest 250/250 (added 10 feedback-action test cases).
