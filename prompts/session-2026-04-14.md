# Session 2026-04-14 — Cycle 51: Feed Comment Replies & Owner Delete (v4.22.0)

## Outcome
Shipped Facebook-style 1-level-deep threaded replies on feed comments plus hard-delete permissions for post owners and admins.

## DB changes
- `ALTER TABLE feed_post_comments ADD COLUMN parent_comment_id uuid REFERENCES feed_post_comments(id) ON DELETE CASCADE`
- `CREATE INDEX idx_feed_post_comments_parent ON feed_post_comments(parent_comment_id) WHERE parent_comment_id IS NOT NULL`
- Applied via Supabase Management API.

## Permission model (hard delete)
`deleteComment()` allows if: comment author OR post owner OR `profiles.admin_role IN ('superadmin','moderator')`. Top-level deletes count replies first, hard-delete the row (cascade removes replies), then decrement `feed_posts.comments_count` by `1 + reply_count` (clamped at 0). Reply deletes decrement by 1.

## Depth enforcement
- UI: no Reply button renders on comments where `isReply=true`.
- Server: `addReply()` fetches the parent row and throws `'Replies to replies are not allowed'` if `parent.parent_comment_id !== null`.
